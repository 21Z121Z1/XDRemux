# XDRemux 技术写作规范

[English](style-guide.en.md) | 简体中文

XDRemux 的当前技术文档采用 ASD-STE100 Simplified Technical English Issue 9 的写作原则。

本项目不声称文档已经正式符合 ASD-STE100。ASD-STE100 标准本身是 STE 的主要依据。本规范只定义 XDRemux 的项目术语和文档发布规则。

## 原始语言

当前技术文档以英文版为 canonical source。

先编写或修改英文版，再把相同的技术含义翻译为中文。不要只在中文版中增加产品行为。

历史证据记录除外。不要为了让旧记录符合当前实现而改写其中的测量结果或结论。

## 写作规则

用户文档、CLI 参考、开发文档、模型卡、测试政策和 Agent runbook 使用以下规则：

1. 同一个对象只使用一个技术名词。
2. 同一个动作只使用一个技术动词。
3. 优先使用主动语态。
4. 每个句子只表达一个主要指令或事实。
5. 如果长句可以无损拆开，就使用短句。
6. 如果条件控制后续动作，先写条件，再写动作。
7. `must` 表示强制要求，`can` 表示能力，`may` 表示可能性。
8. 不使用 *seamless*、*smart*、*easy*、*high quality* 等营销词，除非紧接着给出可测量的定义。
9. 不用口语化同义词替代精确的技术术语。
10. 代码标识符、metadata key、命令参数、文件名和标准名称保持原样。
11. 缩写第一次出现时给出定义，项目术语表中的常用词除外。
12. 明确区分已验证行为、假设、研究观察和依赖真机的结果。

## 项目术语

统一使用以下术语：

| 术语 | 含义 |
| --- | --- |
| `ProXDR` | XDRemux 转换为标准 HDR HEIC 的厂商 HDR 照片格式。 |
| `Gain Map` | 用于从基础图像重建 HDR 的辅助图像和元数据。 |
| `Motion Photo` | 同时包含静态照片和动态视频数据的 Android 照片资产。 |
| `Live Photo` | 共享同一个资产标识的 Apple HEIC + MOV 资源对。 |
| `cover-frame PTS` | 标识源封面帧的呈现时间戳。 |
| `still-image-time` | 标识 Apple Live Photo 静态帧的定时元数据值。 |
| `compressed-sample passthrough` | 不解码、不重新编码，直接复制压缩视频或音频样本。 |
| `OPPO-compatible output` | 由 `--oppo-compatible` 或相关兼容性控制启用的输出模式。 |
| `Photographic Styles` | Apple 功能链路生成的 Apple Photos 摄影风格编辑数据。 |
| `Apple Portrait` | 根据兼容的源景深资源生成的 Apple Photos 人像编辑数据。 |
| `fixture` | 自动化测试使用的版本化输入文件。 |
| `historical record` | 描述特定仓库状态的带日期审计、实验或证据记录。 |

在规范性文档中，不要使用 *live picture*、*dynamic photo* 或 *motion image* 代替 `Motion Photo` 或 `Live Photo`。

## 文档类别

### 当前规范性文档

这类文档描述当前行为或当前维护规则，并同时维护英文和中文版本。

包括根 README、CLI 参考、Apple 功能文档、开发文档、质量政策、验证 runbook、测试 README、fixture README、模型卡和 Agent 验收规则。

### 历史记录

历史记录可能包含旧路径、旧测量值或只适用于某个仓库状态的结论。

不要为了符合当前实现而改写历史记录正文。需要当前说明时，单独增加当前摘要。

### 由代码控制的文本

命令输出、错误信息、metadata key、JSON 字段和源代码标识符属于由代码控制的文本。需要引用精确拼写时，文档必须原样写出。

## 翻译规则

中文版必须和英文版保持相同的技术范围。

以下内容一般保持原样，除非已有明确且更易理解的中文技术名称：

- 文件格式和标准；
- API 和框架名称；
- 命令参数；
- 代码标识符；
- metadata key；
- 路径名称；
- 测量单位。

翻译解释，不翻译标识符。

## 审查清单

完成文档修改前：

1. 根据当前代码、测试或当前验证结果检查每一项行为描述。
2. 检查中英文版本的要求和限制是否一致。
3. 检查所有仓库内链接。
4. 根据当前参数解析器检查命令示例。
5. 依赖真机的行为必须明确标记为依赖真机。
6. 不要把历史观察改写为当前产品保证。
