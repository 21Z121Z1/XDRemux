# CLI 输出政策

[English](logging.en.md) | 简体中文

Rust CLI 负责终端输出和退出状态。本政策适用于面向人的文本、JSON 结果和诊断信息。命令选项见 [CLI 参考](../cli.md)。

## 分开输出流

普通产品命令将进度和结果写入 stdout，将错误写入 stderr。除非 CLI 契约要求，不得另建通用日志协议。

以下命令形式将 JSON 写入 stdout：

- `inspect --json`
- `batch --json`
- `categorize --json`
- `validate --json`

不得在 JSON 输出流中混入无关进度文本。诊断信息与结构化结果面向不同的消费者。

## 编写可操作的错误信息

先说明用户可见的问题。只有内部元数据键或容器术语有助于诊断时，才写入这些细节。

批处理 UI 按行读取失败信息时，保持每项失败占一行。上层添加上下文时，保留原始错误。不得用非结构化 `print` 代替错误处理，再按操作成功继续执行。

## 保持退出状态契约

| 状态 | 含义 |
| --- | --- |
| `0` | 成功、帮助或版本输出。 |
| `1` | 运行时转换或验证失败。 |
| `2` | 命令语法或使用方式错误。 |

适配器和研究工具不得另建一套产品退出码契约。

## 保留有用的诊断信息

部分转换流程通过诊断行报告源信息或产品结果。修改诊断字符串前，搜索是否有测试断言其准确文本。

支持的转换流程可以通过 `--debug-dir` 保留诊断产物。Apple 能力调用失败时，也可以按平台操作的需要保留证据或辅助进程输出。

## 库不负责显示格式

运行时和其他 Rust crate 返回结构化结果、警告和错误，不应依赖终端格式。格式和本地化由 CLI 或 App 显示层负责。

文档与用户可见错误遵循[技术写作规范](../style-guide.md)。
