# ISO 一致性审计摘要：2026-05-11

[English](iso-conformance-audit-20260511.summary.en.md) | 简体中文

[原始审计](iso-conformance-audit-20260511.md)记录了 2026-05-11 的 Python 和 Swift 实现。本摘要说明其适用范围，不认证当前 Rust 实现，也没有重新执行原测试。

## 记录的范围与发现

审计检查了 HDR Gain Map 和 HEIF 表达，覆盖 ISO 21496-1 元数据、项目关系、`tmap` 元数据、色彩属性、位深、方向，以及 Apple ImageIO 兼容性。

原摘要使用以下标签：

| 历史标签 | 数量 | 记录中的含义 |
| --- | ---: | --- |
| `RESOLVED` | 2 | 已修正 Python `hdrgm` XMP 嵌入和 Swift HDRCapacity 映射。 |
| `COMPLIANT` | 9 | 审计接受了列出的容器、色彩、位深和方向检查结果。 |
| `SHOULD GAP` | 1 | Gain Map 使用半分辨率，尺寸与基础图像不同。 |
| `COMPAT CHOICE` | 1 | Python 输出保留了 Apple 可识别的 62 字节 `tmap` 载荷。 |

这些标签是原审计的分类，不是新的标准评估。各项结论的完整表格和代码摘录见原文件。

## 兼容性结果与边界

在记录中的普通输出和直通输出中，Apple 兼容的 62 字节载荷均使 Core Image 报告 `2.4211792945861816` 的亮度余量。严格参考表达的 `ToneMapImage` 载荷为单通道 65 字节或三通道 145 字节，其中包含一字节版本字段。

记录显示，在所测环境中，严格参考输出曾得到亮度余量 `1.0`，或出现加载失败。因此，当时保留了 Apple 兼容载荷，同时保留严格参考辅助实现及其他容器检查。

这个结果区分了标准表达与特定读取方的行为。它不能证明严格表达总会失败，也不能证明兼容表达满足全部标准要求。
