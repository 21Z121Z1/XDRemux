# 摄影风格 HDR 重建

[English](styles-reconstruction.en.md) | 简体中文

`xdremux reconstruct-styles` 从原始 Apple HEIF 照片重建相对场景亮度。它保留原 SDR 主图的压缩数据、颜色属性和几何信息，用新的 RGB ISO Gain Map 承载 HDR 效果。SDR 效果保持不变。

此命令需要 macOS、Metal 和配套的 `xdremux-apple-adapter`。它使用 Apple 私有框架方法，适配器会在调用前检查方法签名。未来的系统版本可能使这项能力不可用。

## 输入与输出

输入必须包含与主图关联的 Styles 元数据、Style Delta Map 和 Linear Thumbnail。当前支持的元数据版本为 `0.8`、`0.9`、`0.15`、`0.16`。命令通过 HEIF 资源关系选择数据，不依赖固定 item 编号、文件名或相机型号。只有风格名称或预设名称不足以完成重建。版本未知、资源不完整、几何信息不一致或消费者检查失败时，命令会明确报错。

```bash
xdremux reconstruct-styles \
  --input original.HEIC \
  --output-dir reconstructed
```

重复 `--input` 可以批量处理。单张失败后继续处理其余输入，每张都有 JSON 结果。只要有一张失败，退出状态就是 `1`。

默认处理原始分辨率。使用 `--max-edge 1024` 可以限制处理分辨率及 Gain Map 的长边，同时限制诊断 EXR 的分辨率。此选项不会缩放或重新编码最终 HEIC 的 SDR 主图。

每张输入生成一个新的 `<source-stem>.reconstructed` 目录：

| 文件 | 用途 |
| --- | --- |
| `hdr.heic` | 保留原 SDR 主图，带重建后的 RGB ISO Gain Map。 |
| `scene_linear.exr` | 用于分析的相对扩展线性 Display P3 重建。 |
| `unstyled.exr` | 应用场景亮度约束之前的原生摄影风格反向处理结果。 |
| `report.json` | 输入和输出哈希、资源编号、原生框架事实、增益范围及回读检查。 |
| `globalToneCurveData.bin` | 原生解析器提供的色调曲线节点。 |
| `lightMapData.bin`、`linearLightMapData.bin` | 原生解析器提供的两张光照数据。 |

## 单独的 HDR 显示目标

使用 `--display-headroom 2`、`4` 或 `8`，可从重建的场景参考 R 生成显示目标 H。此时目录名为 `<source-stem>.display-<headroom>x.reconstructed`，增加 `display_linear.exr`，`hdr.heic` 承载 H。默认命令仍将 R 写入 `hdr.heic`。

```bash
xdremux reconstruct-styles --input original.HEIC --output-dir reconstructed --display-headroom 8
```

显示路径将全局范围映射、粗尺度空间补偿、创作色度／肤色保护分开，不提供苹果 Tone/Color 编辑坐标或二维调色盘。所有容量都使用同一个从场景参考生成的 8x 主目标。2x、4x 文件保存该外观系列对应的端点，分别声明自身容量。

分析在长边不超过 512 像素的面积平均亮度上进行。它以场景／SDR 亮度比的中位数确定曝光，再用分箱中位数拟合单调的全局场景到 SDR 亮度曲线。场景第 2 至第 98 百分位的亮度范围，与拟合 SDR 范围之差，作为范围差距代理。Headroom 是峰值／参考白的比值。这个代理不测量显示黑位、环境反射、绝对场景辐亮度或经过标定的物理动态范围。

全局拟合后剩余的 SDR 空间残差先限幅，再使用跟随场景亮度边缘的联合双边平均，空间 sigma 为 4 像素、范围 sigma 为 0.5 EV。跟随边缘的上采样得到粗尺度场 C，残差限制为 1.5 EV。C 是动态范围补偿的候选场，可能包含创作或语义效果，不能识别相机实际使用的算子。R 的精细细节保留；这条路径不添加锐化或整体模糊。R 本身仍可能带有拍摄阶段的锐化及局部处理痕迹。

干净主目标使用 `A = max(R,0) * exposure` 及全局压缩 `A * 8 / (8 + Y(A))`。颜色阶段参考同一照片扩展线性 SDR 的相对对立色度，保持影调后的亮度并压缩到显示色域。关联的 2026 semantic-person 和旧版 2019 skin 遮罩提供颜色保护权重。缺少 semantic-person 时，可使用关联的 2018 Portrait Effects Matte，并明确记录为前景代理。缺失遮罩使用零权重；存在歧义则失败。天空和新版 skin 资源不会被替代。这些选择不代表完整复现苹果正向渲染器。可独立调用的中间调与皮肤亮度算子仍供研究使用，但在这个范围系列中关闭。

共同目标系列在计算载体增益之前定义。设 `L(v) = log2(max(v,0) + 1/64)`，逐 RGB 分量应用；Q 为干净的 8x 主目标，S 为原 SDR，g 为以 EV 表示的范围差距代理。对于 1 到 8 的 headroom h：

```text
w(h) = log2(h) / 3
lambda(h) = 1 - log2(h) / max(3, g)
B = L(S) - C
L(H(h)) = (1 - w(h)) * B + w(h) * L(Q) + lambda(h) * C
```

1x 目标直接返回原 SDR。其他目标对 L 求逆，再限制到 `[0,h]`。在范围投影和裁切之前，相同偏移量与仿射局部强度使 ISO 21496-1:2025 第 6.3 节的单张 Gain Map 可以表达这个系列。报告同时记录不受单图约束的差距强度 `max(1-log2(h)/max(g,0.01),0)`。当 g 小于 3 EV 时，它比单图强度更早撤掉补偿。本实现明确记录这个折中，不宣称标准文件能执行任意随 headroom 变化的重渲染。对于声明容量为 c 的文件，载体权重为 `log2(min(h,c))/log2(c)`，报告将它与共同 8x 主目标的权重 w(h) 分开记录。RGB 范围投影、输入负分量、采样和编码损失都可能破坏精确一致性。当 g 不超过 3 EV 时，C 在代数上抵消，系列等价于 S 与 Q 的带偏移对数混合。仅当估计差距超过这份容量时，才将实测残差的一部分加入 HDR 主目标。

报告记录全局曲线、差距代理、残差强度／限制、实际遮罩角色／URI／ID／哈希、曝光、有限浮点目标、范围投影比例及原生 headroom／回读。发布之前，适配器从同一份编码文件实际应用 Gain Map，依次测试 1x、1.5x、2x、3x、4x、6x、8x。超过文件容量的请求使用该文件端点。各档相对于该容量下既定目标的平均亮度误差不得超过 0.05 EV。解码负 RGB 和非正亮度保留在误差尾部。报告包含 p99 和最大误差；平均门槛不代表逐像素保证。

声明的显示容量与最大局部增益分别表达。HEVC 量化可能超出浮点界限，并产生接近黑色的负值。原生回读及 SDR 不变性不证明真实 HDR 观看质量。原有纹理元数据保留，不重跑纹理渲染器。机制与证据边界见[影调与颜色方法](research/styles-tonal-color-methods.md)。

EXR 像素使用显示方向。重建计算使用存储方向，以保持辅助资源与压缩 SDR 对齐。EXR 编码器可能使用半精度，报告记录实际回读误差。

已有输出目录不会被替换。同一输出目录下重复的输入文件主名会明确报错。报告最后写入。调用失败时只删除本次创建的目录，原照片始终只读。

## 重建与验证

1. Rust 提取关联的元数据及完整辅助图像子图，防止 ImageIO 通过替代图像组选择回其他主图。
2. 适配器向 Apple 获取反向配置与调参，依据原生纹理尺寸检查系数存储。Delta Map 根据其自身存储尺寸独立映射到主图画布。
3. Apple 反向处理器提供撤销摄影风格后的颜色，原 HDR 提供精细亮度细节。
4. Rust 用实测原生指数反函数 `2^((code - 0.69336945) / 0.08550479) - 0.00964052` 解码 Linear Thumbnail，计算有界的亮度增益场，并按下述方法约束弱主图结构中的转移，再使用跟随主图亮度边缘的联合双边插值。原生 YCbCr 转 RGB 可能产生少量超出名义编码范围的数值；这不会触发另一套传递函数。
5. 一个稳健的全局标量保留原 HDR 的中间调曝光。运行时不使用 RAW 文件、逐机型拟合、按文件名设定的参数或训练模型。
6. Rust 相对于原 SDR 计算 RGB 增益。负增益可以压低 HDR 阴影。统一的 `1/64` 偏移量让黑位增益保持有限。Gain Map 使用 HEVC 4:4:4 编码，原压缩 SDR 图像树直接复制。
7. 派生 `tmap` 使用主图显示尺寸及恒等旋转。把竖拍主图的旋转再次复制给派生图像，会使 ImageIO 忽略 ISO Gain Map。
8. 成功前检查压缩 SDR 一致性、原生 SDR 回读、原生 HDR 展开、EXR 回读和输入完整性。SDR RGB 误差不得超过 `1e-6`；HDR 与目标的平均亮度误差不得超过 `0.15 EV`；EXR 平均亮度往返误差不得超过 `0.005 EV`。

生成的 HEIC 保留输入元数据和辅助资源。已有 Styles 资源仍描述原始拍摄。本命令不证明修改 Gain Map 后，Photos 内后续交互式摄影风格编辑仍与原文件等价。

## 以原图引导平坦区域的增益

缩略图可能含有原渲染已压低的低频亮度结构，直接转移全部差异会使平滑表面变得不均匀。因此，使用完整分辨率的线性 SDR base 作为结构引导，先约束这部分转移，再定义 R 和显示系列。SDR base 不提供目标场景亮度。这是外观约束，不能识别哪些变化是真实照明或拍摄伪影。

分析在长边最多 512 像素的面积平均线性亮度上进行。在 SDR base 的半径 4 邻域内测量 log 亮度方差，标准差低于 0.075 EV 的像素形成候选区域，通过 log 亮度相差不超过 0.1 EV 的四邻居连接。区域至少包含 64 像素，base 亮度跨度不得超过 0.4 EV。邻域半径随分析长边缩放，最小面积随其平方缩放。无效节点不参与。

合格区域采用曝光锚定后，缩略图／原 HDR log 增益的中位数。候选样本至少 90% 与中位数的偏差不超过 0.25 EV，且内点数量仍须满足最小区域面积。只有这些内点形成普通平坦核心，离群点保留原引导，除非满足下述细结构条件。大范围场景差异无法满足这个支持比例。若被细文字或分隔线分开的核心区域距离不超过半径 16、base 平均亮度相差不超过 0.1 EV、合并 base 跨度不超过 0.4 EV，且合并增益跨度不超过 0.5 EV，则共用一个增益。半径随分析长边缩放。合并样本的中位数会投影到使每个核心样本改变量都不超过 0.25 EV 的区间，避免同一表面形成多个亮度平台。恒定增益向半径 4 的兼容边界带延伸：base 亮度必须位于区域范围加减 0.1 EV 内。内侧一半使用全强度，外侧一半以三次 smoothstep 衰减到零，半径随分析长边缩放。其他区域保留原缩略图引导。

联合双边插值逐点使用完整分辨率 SDR base 作为范围引导，范围 sigma 为 0.5 EV，支持域为 4×4，将定义的区域增益与原插值增益混合。每个原尺寸像素通常不超过 0.25 EV，下文说明细结构例外。先定义恒定增益再插值，避免仅重采样差值后残留缩略图起伏。像素仍使用原 HDR 的精细亮度和撤销风格后的颜色，主图 RGB 不做空间平均。这不能保证真实照片纹理完全不变，也不能排除所有光晕。

细文字、分隔线等小结构需要单独判断。使用 SDR base log 亮度的半径 3 中值作为表面引导，偏差超过 0.1 EV 时仅识别为候选小结构；中值滤波后仍保留的大范围阶跃不触发。附近必须存在合格的平坦核心，并与中值表面的亮度相符。半径随分析长边缩放。

成对的线性缩略图／原 HDR 样本必须支持正相关的局部仿射关系，候选才被接受。先尝试分析像素半径 0、1、2 的主图方框模糊，考虑缩略图模糊后再估计反差，不搜索空间平移。每个模型用局部窗口中交替的像素拟合，其余像素验证：有效支持至少 90%，正相关系数至少 0.5，主图方差超过 `(meanHDR * 0.02)^2`，留出像素的 log 亮度 RMS 误差不超过 0.1 EV。斜率除以核心增益后必须在 [0.25,4] 内，模型预测的背景还必须与平坦核心相差不超过 0.1 EV。这是亮度模型路径，只有这条路径可以定义前景反差。另有仅背景路径：要求相关系数至少 0.9，推断的背景与核心差异不超过通常的 0.25 EV 平坦区预算，但不把不确定的斜率用于前景。它仅修改完整分辨率 SDR 像素落在已接受核心的观测亮度范围内、或距离该范围不超过 0.1 EV 的位置，并平滑过渡，距离达到 0.2 EV 时不执行修正。使用核心范围而不是被笔画污染的局部中值，保留主图背景原有的暗侧下冲，只去除其周围新增的增益。两条路径均不通过的候选不做细结构修正。接受的种子向周围扩展，半径 3 内使用全强度，至半径 6 平滑衰减到零。报告分别记录候选、亮度模型通过和仅背景通过的种子数。

对每个原尺寸像素，设 `x = originalHDRY / medianHDRY`、k 为核心的线性增益、c 为相对斜率。`c >= 1` 时使用 `t = smoothstep(clamp((abs(log2(x))-0.15)/0.5,0,1))` 和 `a = 1+(c-1)*t`，0.15 EV 背景带保留原有精细背景纹理。`c < 1` 时使用 `a = c`，允许真实前景反差降低，并避免产生非单调的过渡。亮度模型目标为 `k * medianHDRY * max(1+a*(x-1),1e-6)`，每个固定模型对主图亮度保持单调。仅背景证据保留前景原来的增益路径，只约束匹配的背景像素。正权重联合插值在 log 增益域混合这些对齐的目标。主图像素不做空间平均，也不复制缩略图里变宽的轮廓。

回归包含渐变、密集纹理和细小高光组成的恒等输入；缩略图模糊后的笔画；HDR 前景反差高于和低于主图的两种情况；错位和反向结构；缺乏平坦参考的密集纹理；宽边缘及大幅真实场景差异；还验证仅背景证据不得定义前景影调的不变量。这些测试覆盖具体失效模式，不能证明所有场景分类正确。尤其是，微弱的真实光照差异与缩略图误差可能产生相同的可用观测。因此，平坦表面正则化是一种有界的外观先验，不能证明缩略图中的内容就是错误。SDR base 更清晰或通过这些样例，都不能构成物理场景恢复的保证。

通常仍使用 0.25 EV 的改变量上限，仅在低分辨率比值不可靠的细结构支持域内，随插值权重向 1.5 EV 提升，以去除超出平坦表面预算的错误字边增益。它不是通用文字检测，也不能恢复原始光学点扩散函数，源照片已有的锐化和彩边仍可能保留。

报告记录引导来源、分析尺寸、策略、合格区域数量及比例、细结构比例，以及实际原尺寸改变量 RMS 和最大值。默认场景输出与独立显示输出都使用经过约束的 R，原 SDR 保持不变。该策略会牺牲一部分缩略图或 RAW 一致性，以换取平坦表面的稳定；仅凭 RAW 一致性不能决定最终显示外观。它不会消除所有继承的局部处理问题，也不能恢复经过物理标定的场景。

## 限制

结果是相对场景亮度近似，不是 RAW 恢复，也不证明完整撤销了拍摄 ISP。内嵌缩略图的分辨率和精度有限，主图已经丢失的颜色和细节不能恢复。正值 HDR Gain Map 无法精确表达负线性颜色通道，因此 HEIC 输出会将它们裁到零，并在报告中记录比例。

色调曲线和两张光照数据解码后用于检查。这不等于已经确定完整的拍摄色调映射组合。运行时不会把两张光照图相除后就称为 ISP 逆变换。

当前路径在趾部也使用实测原生指数反函数，尚未证明它就是所有历史 Styles 文件的精确拍摄传递函数。未知元数据版本会明确拒绝。能力检测和回读检查不能替代更多场景的 RAW 对照。

此阶段不标定绝对辐亮度或漫反射白，尤其没有把漫反射白定义成 203 nits。HDR 显示自适应及真实 Photos／设备观感需要单独的消费者证据。
