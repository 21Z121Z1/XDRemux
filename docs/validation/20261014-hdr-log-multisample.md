# HDR Log 缩略图：15 张照片的原生对照

简体中文 | [English](20261014-hdr-log-multisample.en.md)

替换直接复制的 SDR 缩略图后，有响应的 version 16 研究载体的 Tone 响应得到改善：方向检查从 4/15 提升到 14/15，默认 look 保持不变。当前 version 15 产品载体在此原生诊断中仍未激活调整。这是两个不同的结果。

## 输入与控制变量

样本包括全部 14 张已入库的 OPPO ProXDR 夹具，以及此前测试的私有蓝窗帘照片。Find X6 Pro 为 1 张，Find X7 Ultra 为 6 张，Find X9 Ultra 为 8 张，覆盖 LHDR、RGB UHDR、XPAN、高像素、大师模式和人像输入。这不是随机样本；两张 Master-v2 照片是构图相近的日落场景。

每张原图有四个输出：version 15 的 SDR 缩略图版、version 15 的 PR HDR Log 缩略图版、version 16 的 SDR 缩略图版，以及 version 16 使用相同 PR 缩略图的版本。PR 缩略图直接取自实际 Rust 转换结果，没有在 Python 中重新实现变换。

同一载体的每组对照，仅替换缩略图有效载荷及匹配的 HEVC 配置。Key1、完整 Styles plist、主图、Gain Map、语义资源、尺寸和缩略图方向均保持不变。每张照片的两代 source-derived 载体的曝光 key `4` 相同。15 张原图的资源检查全部通过，执行前后核对了源文件及可执行文件哈希。

原生渲染覆盖 disabled、neutral、Tone −1、Tone +1、Color −1、Color +1、Tone −1 / Color +1 和 Tone +1 / Color +1，固定 Standard cast、intensity 1、最大尺寸 1024。主矩阵 480 张渲染全部成功。另外生成 14 张渲染，复核剩余的方向例外和一次一码值的重复性差异。平台为 macOS 27.0.1 build 26A434，PNG 输出为 Display P3。

## 测量结果

当控制状态相对 neutral 的 RGB MAE 超过 0.05/255 时，计为调整生效。对生效的载体，方向检查要求 Tone −1 的平均线性 P3 亮度降低、Tone +1 的平均亮度升高，容差为 0.001 EV。上述标准在渲染前确定；未激活的样本不计为方向成功或失败。

| 指标 | 复制 SDR 缩略图 | HDR Log 缩略图 |
| --- | ---: | ---: |
| version 16 激活调整的照片 | 15/15 | 15/15 |
| version 16 Tone 方向检查通过 | 4/15 | 14/15 |
| version 16 Tone −1 错误地提高平均亮度 | 11/15 | 1/15 |
| version 16 Tone +1 提高平均亮度 | 15/15 | 15/15 |
| version 16 每组 neutral 像素相同 | — | 15/15 |
| version 16 每组 disabled 像素相同 | — | 15/15 |
| version 15 激活调整的照片 | 0/15 | 0/15 |
| version 15 每组 neutral 像素相同 | — | 15/15 |

10 张从方向检查失败变为通过，没有通过样本退化为失败。剩余例外为 `uhdr-hr-02`：Tone −1 相对 neutral 从 +0.41865 EV 缩小到 +0.03115 EV，后者约为平均亮度提高 2.18%。包括两次重复运行在内的三次观察结果相同。该样本仍按方向检查失败记录，没有放宽容差。

组合端点饱和比例有 12 张降低超过 0.01 pp，其余 3 张变化不超过 0.01 pp，没有增加。逐张平均变化为 −0.59657 pp，中位数为 −0.06549 pp。两张 Master-v2 样本分别从 11.08144% 降至 7.76647%、从 11.68849% 降至 8.45095%。

Tone −1 下，纯黑像素（三通道均为零）比例有 14 张降低超过 0.01 pp，XPAN 样本降低更少，没有增加。15 张新版的 Tone +1 仍然提亮，但平均亮度提升幅度均小于旧版。因此，饱和比例变化不等于在同亮度下恢复了高光细节，也不能证明 HDR 显示裁切减少。

version 15 矩阵中，一组 disabled 对照有一个通道相差一个 8-bit 码值，RGB MAE 为 0.000000424/255。重复渲染同一个未修改的 SDR 文件也出现相同的一码值变化。所有 version 15 成对文件的 neutral 和调整端点像素均相同；此诊断仍未测到该载体的 Tone 或 Color 调整激活。

## 来源与边界

PR 实现在 `e04c1a9` 上测量。实际使用的可执行文件 SHA-256 为：

- PR CLI：`4b63b0ec649f92986fa7651dae371eb9049f66835bbe582cc830e4a200460688`。
- 归档 version 16 CLI：`2fc2cf158bf1acad164d57e890fb30e8280310292007b0eaa38d41b66ed1fb1b`。
- 原生渲染器：`476a36a38a88f6860c8dbb6c21133c1c40e1d0dc565a4c257c03e632be51afd7`。

version 16 producer 是按哈希固定的归档研究二进制，其源码参照为 `9897b86`；本实验不宣称对归档 producer 进行了新的 exact-HEAD 构建。实验协议、可执行文件快照、源文件哈希、资源检查、原始 manifest、PNG、分析脚本和 CSV 均保存在本地。私有原图和照片渲染不属于公开仓库产物。

两代载体之间的差异不止版本号，本实验不能证明只改 version 字段就能启用 Styles。但在各自载体内部，缩略图是隔离出的唯一变量。

结果支持在能响应的 consumer 路径中使用 HDR Log 缩略图。它不证明当前 version 15 产品载体已有可见收益，也不证明 RAW 恢复、完整 key1 求解的替代、完整转换提速、Photos 导入／编辑／保存／重开或设备 HDR 显示效果。较小的[编码资源回归](20261014-hdr-log-thumbnail.md)仍作为自动化产品检查。
