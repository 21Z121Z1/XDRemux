## Minimal product design, pending implementation assignment

1. Add one typed representation choice, `pair | pvt`, default **pair**, exposed consistently as **`--live-photo-output pair|pvt`** in the shared convert/batch argument group (`crates/xdremux-cli/src/lib.rs`, `ProductConversionArgs`). Keep it separate from Standard/OPPO media intent and Portrait/Styles/Cinematic capabilities. The engine owns typed user intent; runtime owns destination layout, validation and filesystem effects. Preserve current method/default behavior for callers that do not choose PVT.
2. Add the same enum-backed choice to App `ConversionConfig` in `AppModels.swift`, rendered beside output settings in `ContentView.swift:SettingsView`. `RustCLIClient` forwards the choice; Swift performs no package creation, metadata mutation or fallback reencoding. The setting applies to Live Photo items, with ordinary still conversion unchanged. Reject an explicit `.pvt` destination for an incompatible non-Live-Photo conversion, rather than producing disguised media.
3. Generate and validate the media pair **once** through the existing runtime. After that common boundary, route either to the unchanged flat-pair publisher or to PVT staging. Packaging copies/writes the exact validated still/MOV bytes plus the fixed plist. Do not generate a second asset ID, remux again, normalize metadata, or invoke makelive/AVFoundation. Existing conversion omission reporting still applies: wrapping the product pair does not mean every Android vendor resource was embedded.
4. Stage all three members under an operation-owned private directory in the destination filesystem. Names must be safe single components and unambiguous, with one shared media stem. Validate staged members through pinned `Input::ApplePair`, check plist type/version and full pair-byte preservation before publication.
5. Publish the **one completed package directory** with an atomic exclusive/no-replace directory rename. macOS has `renamex_np`/`RENAME_EXCL`; Linux has `renameat2(RENAME_NOREPLACE)`, exercised here. Prefer an established safe Rust binding if adding this backend; `std::fs::rename` plus an existence precheck can replace an existing empty directory and is insufficient. Flat-file hard links cannot publish a directory. Do not wrap arbitrary caller paths in deletion-owning tempfile guards. Unsupported backends/filesystems fail closed with their original I/O error; do not silently use an overwriting rename. A small platform backend is sufficient, not a generic transaction framework.
6. No existing final package is overlaid, unlinked or recursively reconciled. Failed publication cleans only its own staging; retained/ambiguous generated state must be reported without assuming deletion authority over a final path. A single directory rename can make these three names visible together, but no claim of power-loss durability follows without directory syncing. This also cannot prevent an external writer from actively modifying a published package.
7. Add directory support to Rust `validate`, using a bounded package reader for the supported recipe and the existing media parser. CLI/App reuse and batch checkpoints must distinguish the chosen container: a completed flat pair cannot satisfy a PVT request. Package receipts should expose the package path (and member paths when useful); existing pair receipts remain unchanged. Batch output planning reserves the outer package path and retains source provenance. App previews can use the still member/source, while output reveal/open uses the package.

The current shipping target is arm64/macOS 27. Keep byte layout, metadata handling and media validation portable Rust; isolate any directory-publish backend by platform so other Rust core targets continue to compile. The Linux prototype is portable-core evidence only. Windows/FAT/exFAT/native-macOS success is not established by this experiment. Apple's [exclusive-renaming capability](https://developer.apple.com/documentation/foundation/urlresourcekey/volumesupportsexclusiverenamingkey) is volume-dependent; Linux likewise [requires filesystem support for NOREPLACE](https://www.man7.org/linux/man-pages/man2/rename.2.html).

| Boundary | Regression assertions |
| --- | --- |
| Default and request types | Omitted option equals current pair behavior; explicit pair matches default; PVT routes only supported Live Photo work; media intent/Apple-feature conflicts stay deterministic. CLI/App arguments and output extension agree. |
| Package round trip | Write/read/export same still and MOV hashes; same asset ID, exact integer/timescale presentation, encoded samples, track references and all existing media metadata/auxiliary resources; plist parses and has string `"1"`; no encoder/remux is entered by the packaging step. |
| Image families | Existing public HDR HEIF and SDR/JPEG pairs retain their actual file format, Gain Map and byte hashes. Test JPEG in the package reader independently of the CLI's currently HEIF-only flat validator. Historical Snoopy fixture is a separate gate when accessible. |
| Error inputs | Missing/invalid plist; integer/bool instead of string; missing/unsupported version; missing still or MOV; truncated media; absent/mismatched identity; missing timed metadata; unexpected nesting/symlink/nonregular member; multiple still/MOV candidates and case-fold ambiguities. Reject unsupported shapes without deleting their bytes. |
| Disguised archives | A regular ZIP file renamed `.pvt` is rejected, with no archive extraction or traversal. A transport `.zip` is not claimed as a native package output. |
| Duplicate requests and provenance | Same source twice, same stems from distinct inputs, existing valid/invalid/partial packages, and prior pair checkpoints. Only provenance-matching reuse succeeds; unknown packages are preserved, not adopted or cleaned. |
| Publication and concurrency | Existing empty/nonempty dir, file, symlink and post-preflight competitor; simultaneous same/different outputs; exactly one winner for a shared destination; no replace, unlink or overlay of competing members; failure keeps source and prior/competing package hashes. |
| I/O failure and recovery | Creation/write/sync/validation/exclusive-rename failure; unsupported no-replace backend/volume; cancellation/crash around publication. Clean only operation-owned staging; report retained bytes/path and keep original error chain. State visibility and power-loss guarantees must be named separately. |
| Consumer and native target | `xdremux validate asset.pvt`, batch JSON/path/checkpoint behavior and App reuse/open/reveal tests. On arm64/macOS 27, inspect package recognition and Photos import as a separate native gate; use a device only for any future wallpaper claim. |
