## Delivered behavior and boundaries

The CLI accepts a global `--lang` (`en` / `zh-CN`, including normalized locale forms). Resolution is explicit option, `XDREMUX_LANG`, `LC_ALL`, `LC_MESSAGES`, `LANG`, English. Empty environment values are skipped. An unsupported environment locale selects English; an unsupported explicit option remains a usage error. Descriptions are translated before clap rendering; messages translate CLI-owned labels/context at the call site. User path arguments stay `OsString`/`PathBuf`; command names, options/enums, machine JSON, and exit codes retain their existing contract. Parser details and underlying/native errors can remain English. This does not claim complete diagnostic translation or successful JSON serialization of arbitrary Unix pathname bytes: the existing inspection `PathBuf` serializer rejects non-Unicode paths, and the new regression preserves that failure and byte-identical stdout across locales while proving human inspection can still read the original path.

The port retains current Cinematic parser options, intent routing, feature conflicts, Motion Photo omission reporting, batch omission JSON, and native `validate --apple-styles`. No runtime, HDR policy, semantic implementation, Styles scripts, native sources, root package graph, AGENTS, or project skills were changed by this reviewer. The root package continues to include both `XDCinematicNative` and `XDTextureNative`.

Pinned source builds, Mach-O closure staging/audit, ad-hoc signing, source/license preservation, and normalized archive generation live in `scripts/distribution`. `rust-cli-core.yml` owns the additional two architecture jobs; the repository remains at six workflows. No historical apply/migration workflow or second installer/runtime was restored. Archive normalization proves repeatable archives for the same staged bytes and epoch, not reproducible compiler outputs.

`distribution-i18n-files.json` lists the 20 frozen scope files and SHA-256 of each. It names the actual source HEAD and dirty state at freeze; subsequent parent commits must get their own exact-HEAD evidence.

## What relocated package CI actually checks

After checksum-pinned native builds and the current Rust/Swift root builds, staging walks all Mach-O load kinds (including weak/reexport/upward/lazy), rewrites each non-system dependency to package-relative `@loader_path`, rejects dependencies outside the pinned prefix, removes non-system rpaths, and re-signs. Audit requires exactly the four intended dylibs, matching architecture, no embedded dyld environment, no unaccounted load dependency, and strict signatures. It records hashes/load facts and actual host OS/toolchains.

The emitted archive is checksum-verified and extracted into a fresh scratch directory outside the checkout, including a path with spaces. Extraction rejects traversal, links, duplicate/case-colliding names, and multiple roots. The extracted package is audited again. Source HEAD/architecture must match its manifest. Each binary invocation uses actual `/usr/bin/env -i`, a temporary HOME/TMPDIR, system-only PATH, and a working directory outside the checkout. dyld traces must contain the bundled libheif for CLI calls and must not contain a non-system library outside the package, including Homebrew paths.

The smoke exercises both help languages and the bundled adapter's current schema-2 capabilities handshake. It checks fixture SHA-256 against `fixtures/SHA256SUMS`, copies inputs into scratch, and converts Samsung `motion-photo/samsung/heif-ultrahdr-01.heic` and OPPO `proxdr/oppo/find-x6-pro/lhdr-v1-01.heic`. It validates both Samsung HEIC and MOV with the current CLI schema-1 outer document (`valid: true`, `kind: live-photo`), and the OPPO output as `iso-hdr-heif`. The source and copied input hashes must remain unchanged. A repeated pair conversion must fail without changing either published member. stdout/stderr, command statuses, output hashes, source/notice identity, linkage, timeouts, and cleanup status remain outside disposable scratch as artifacts, including failure paths.

These checks are executable CI requirements, not an already observed macOS result. `native_feature_acceptance` stays false in the smoke report; a generic adapter handshake does not certify private APIs, Styles/Texture, Cinematic generation, Photos editing, or device behavior.
