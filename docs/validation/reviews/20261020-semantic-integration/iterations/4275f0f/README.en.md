## Direct PVT import probe and its limits

`04c09aa` adds a job to the existing Research workflow, portable boundary tests
and the verification recipe. `4275f0f` explicitly makes three stateless reader
worker methods nonisolated while retaining UIKit window/delegate isolation.
The [eleven-file author review](4275f0f-author-review.json) binds final bytes.
The [original frozen probe](pvt-native-import-prototype/README.md) is an
independent implementation starting point, not the inaccessible historical
Snoopy sample or its exact script. Root integration additionally restricts the
reported app-container UDID to a whole path component and adapts source names,
workflow ownership, public recipe and Swift worker isolation.

On the free standard macOS27/arm64 runner the job builds the current CLI,
creates nonprivate geometric JPEG/H264 source frames through Apple APIs,
converts to the optional real PVT directory, validates its pair and string
plist version, and creates a uniquely owned simulator. The sole import call
passes **the entire PVT directory** to native `simctl addmedia`. No unpacked
member import, PhotoKit creation or pairing fallback is permitted. Only the
exact created simulator and installed test bundle may receive the documented
official per-app Photos grant. No host TCC/database or real user library is used.

Read-only PhotoKit compares baseline/delta IDs, requires one new Live Photo,
reads its original photo/pairedVideo resources, and verifies original hashes,
MakerApple17/video identifiers and timed cover metadata. Post-import exports
are readback only. Input/package preservation is checked on failure too.
Original stdout/stderr/status and exact owned shutdown/delete outcomes survive.
Missing runtime/SDK/grant/GUI capability, rejected package, timeout, unreadable
resource or cleanup failure is a non-PASS. Even a simulator PASS would not prove
physical-device editing, wallpaper qualification or historical sample byte
identity. No actual native import PASS is claimed by this appendix.

The [Linux preflight](04-native-linux-block/result.json) actually fails at
missing `xcrun` and exits2. The separate [synthetic CLI precondition](04-synthetic-cli-precondition/manifest.json)
uses Pillow/FFmpeg surrogate generation and passes real inspect→PVT convert→
validate with source bytes unchanged. It does not execute AVFoundation's new
generator or any Photos import. Generated media and decoded pixels remain local;
only an explicit text/code/hash allowlist is included here.
