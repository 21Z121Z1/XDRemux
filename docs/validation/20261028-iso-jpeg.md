# ISO JPEG 元数据与替代 ICC 兼容性

[English](20261028-iso-jpeg.en.md) | 简体中文

本记录覆盖 2026-10-28 的 JPEG 增益图后续修复。样本身份以 [SHA256SUMS](../../fixtures/SHA256SUMS) 为准；原始文件和清单保持不变。测试及 CI 回执另行标识被测提交。

## 样本审计

下列基线 ICC 均声明三分量 `RGB `、带 `acsp` 签名，且标签表与标签数据均未越界。它们均不含 `cicp`。所有已定位的 HDR 增益 JPEG 均没有 ICC。基线 JPEG 中只含版本的 ISO APP2 不参与增益元数据选择。

| `fixtures/motion-photo/` 下的 JPEG | 增益元数据 | 基线 ICC 字节数 / 声明大小 | 替代 ICC |
| --- | --- | --- | --- |
| `samsung/jpeg-ultrahdr-01.jpg` | ISO + XMP | 632 / 632 | 缺失 |
| `samsung/jpeg-ultrahdr-02.jpg` | ISO + XMP | 632 / 632 | 缺失 |
| `xiaomi/android-v1-ultrahdr-01.jpg` | ISO + XMP | 632 / 632 | 缺失 |
| `oppo/coloros15-ultrahdr-01.jpg` | XMP | 548 / 548 | 缺失 |
| `oppo/coloros15-ultrahdr-02.jpg` | XMP | 548 / 548 | 缺失 |
| `oppo/coloros15-ultrahdr-03.jpg` | XMP | 548 / 548 | 缺失 |
| `oppo/coloros16-dualstream-ultrahdr-01.jpg` | XMP | 548 / 548 | 缺失 |
| `oppo/coloros16-dualstream-ultrahdr-02.jpg` | ISO + XMP | 548 / 548 | 缺失 |
| `vivo/android-v1-sdr-01.jpg` | 无增益图 | 548 / 548 | 不适用 |
| `vivo/android-v1-sdr-02.jpg` | 无增益图 | 556 / 548 | 不适用 |

第二张 vivo 对照样本的 ICC 比头部声明大小多八字节，现有基线 ICC 路径接受它。如果把替代配置文件的长度检查全局应用，会改变已接受行为，因此本修复不收紧基线 ICC 准入。HDR 基线缺少 CICP 的处理也不在本次仅针对替代 ICC 的改动中。

八张 HDR JPEG 的 XMP 均为 `HDRCapacityMin=0`、`HDRCapacityMax>0`，与新增 capacity 检查没有真实样本冲突。XMP 字段省略时的现有默认值保持不变。ISO 数值独立保留：Samsung 的增益及替代 headroom 为 `2.299999952316284`，不是 XMP 舍入后的 `2.300000`；Xiaomi 为 `1.5849624872207642`；双格式 OPPO 为 `2.300448417663574`。四张双格式样本均使用一个元数据分量和基线应用标志。

## 兼容性决定

启用替代 ICC 拒绝规则前，完整十张 JPEG 的运行时矩阵通过，在 Linux 验证主机耗时 187.89 秒。由于这些样本均不提供替代 ICC，最低 ISO 替代配置文件检查不会拒绝基线中的任何样本，可以随 P1 一起提交而不改变已支持的真实样本集合。新的替代配置文件必须通过文档规定的最低检查；存在但损坏的配置文件会产生明确的替代 ICC 错误，不自动替换 ICC，也不回退到 SDR。

这些样本不包含真实 HDR 替代 ICC 正例。合成准入头部覆盖 CICP 解析与非法边界，真实 SDR ICC 覆盖 headroom 递减的替代配置文件路径。这些检查不证明完整 ICC 符合性、CICP 与变换的数值等价、原生 HDR 显示或图库行为。更广的 ICC 校验和新增真实替代配置文件兼容性需要独立证据。

## 复现行为检查

使用已配置的 Rust/libheif HEVC 环境，执行：

```bash
cargo test --locked -p xdremux-metadata
cargo test --locked -p xdremux-runtime --test iso_jpeg_metadata
cargo test --locked -p xdremux-runtime --lib live_photo::tests
cargo test --locked -p xdremux-runtime --test live_photo_jpeg_fixtures \
  real_jpeg_motion_photo_vendor_matrix -- --ignored --nocapture
python3 -m unittest tests.test_public_documentation tests.validation.test_repository_layout
(cd fixtures && sha256sum -c SHA256SUMS)
```

公开运行时接口的回归检查已发布 HEIF 中选中的 ISO 数值及标志、三组相同的元数据分量记录、独立的 base/gain/tmap 色彩属性、Exif sRGB 优先级和 XMP-only ICC 隔离。结构校验器检查有序 `[base, gain]` 引用。非法 ISO 即使伴随有效 XMP，也会在发布前失败，覆盖已映射与未映射 GainMap 两种情况。非法替代 ICC 同样在发布前失败。测试保留输入及已有输出对照。

修复前的元数据实现未通过四组针对性回归：ISO 优先级、非法 ISO 回退、ISO 数值约束、XMP capacity 约束。原替代 ICC 路径也会发布故意损坏的配置文件；接入准入检查前，相应回归失败。修复后通过的结果必须以提交 HEAD 对应的回执为准，不能使用早期基线或 PR #83 的结果代替。

## 来源与解释

- [ISO 21496-1:2025](https://www.iso.org/standard/86775.html)，5.2.5.3、5.2.7、5.3、6.3、附录 B.2、C.2 和 C.4。提供的原文以扫描页阅读。C.2.1 允许可选尾部；C.2.3 说明通用阅读器对未知版本的处理。转换器拒绝是 XDRemux 策略。
- [Android Ultra HDR v1.1](https://developer.android.com/media/platform/hdr-image-format)，ISO 兼容指导和 hdrgm 字段约束。跨格式 ISO 优先级来自 Android 建议。
- [HEIF 色调映射修订](https://www.iso.org/standard/89044.html)。本次两份 HEIF 中文附件不可用，公开英文预览只含定义，未提供 6.6.2.4。本修复保留既有 HEIF 图关系及编码契约，不声称完成了新的 HEIF 全文符合性审查。
- [ICC.1:2022](https://www.color.org/specifications/ICC.1-2022-05.pdf) 的头部、标签结构、9.2.17 和 10.3；[H.273（07/2024）](https://www.itu.int/rec/T-REC-H.273-202407-I) 的 CICP 代码点。RGB ICC 的矩阵 0 与增益压缩 nclx 的矩阵 6 描述不同编码。
