English | [简体中文](20261028-iso-jpeg.md)

This record covers the 2026-10-28 JPEG gain-map follow-up. Fixture identity comes from [SHA256SUMS](../../fixtures/SHA256SUMS); the original files and manifest remain unchanged. Test/CI receipts identify the tested commit separately.

## Corpus audit

The second vivo control includes eight bytes beyond the ICC header's declared size. The existing baseline ICC path accepts it. Applying alternate-profile length checks globally would change that accepted behavior, so this repair does not tighten baseline ICC admission. HDR baselines with missing CICP remain outside this alternate-only change.

All eight HDR JPEGs have XMP `HDRCapacityMin=0` and `HDRCapacityMax>0`. There is no real-sample conflict with the added XMP capacity checks. Existing defaults for omitted XMP fields remain unchanged. ISO values are independently preserved: Samsung's gain and alternate headroom are `2.299999952316284`, rather than XMP's rounded `2.300000`; Xiaomi's are `1.5849624872207642`; the dual-format OPPO's are `2.300448417663574`. All four use one metadata component and the baseline-application flag.

## Compatibility decision

Before enabling alternate ICC rejection, the complete ten-JPEG runtime matrix passed (187.89 seconds on the Linux validation host). Because none supplies an alternate ICC, the minimum ISO alternate-profile checks do not reject any member of this baseline. They can accompany P1 without changing the supported real-sample set. A new alternate profile must pass the documented minimum checks; a damaged present profile fails with an explicit alternate ICC error. There is no automatic ICC substitution or SDR fallback.

This corpus supplies no real positive HDR alternate-ICC example. Synthetic admission headers exercise CICP parsing and invalid bounds, while a real SDR ICC exercises the decreasing-headroom alternate-profile path. These checks do not establish complete ICC conformance, CICP/transform numerical equivalence, native HDR rendering or gallery behavior. Broader ICC validation and additional real alternate-profile compatibility need separate evidence.

## Reproduce the behavior checks

Use the configured Rust/libheif HEVC environment. The portable checks are:

```bash
cargo test --locked -p xdremux-metadata
cargo test --locked -p xdremux-runtime --test iso_jpeg_metadata
cargo test --locked -p xdremux-runtime --lib live_photo::tests
cargo test --locked -p xdremux-runtime --test live_photo_jpeg_fixtures \
  real_jpeg_motion_photo_vendor_matrix -- --ignored --nocapture
python3 -m unittest tests.test_public_documentation tests.validation.test_repository_layout
(cd fixtures && sha256sum -c SHA256SUMS)
```

The public runtime regression checks selected ISO values and flags in the published HEIF, all three equal metadata component records, independent base/gain/tmap color properties, Exif sRGB precedence, and XMP-only ICC isolation. The structure validator checks ordered `[base, gain]` references. Invalid ISO with valid XMP fails before publication both with and without a mapped GainMap. Invalid alternate ICC also fails before publication. Tests retain the input and existing output controls.

The original metadata implementation failed four focused regression groups before the repair: ISO priority, invalid-ISO fallback, ISO numeric constraints, and XMP capacity constraints. The original alternate ICC path also published a deliberately damaged profile; its regression failed before the admission check was connected. Passing-after results must be taken from a receipt for the submitted HEAD, not from the earlier baseline or PR #83.

## Sources and interpretation

- [ISO 21496-1:2025](https://www.iso.org/standard/86775.html), 5.2.5.3, 5.2.7, 5.3, 6.3, Annex B.2, C.2 and C.4. The supplied original was read as scanned pages. C.2.1 permits optional tails; C.2.3 describes general-reader handling of unknown versions. Converter rejection is XDRemux policy.
- [Android Ultra HDR v1.1](https://developer.android.com/media/platform/hdr-image-format), ISO compatibility guidance and hdrgm field constraints. Cross-format ISO priority is Android's recommendation.
- [HEIF tone-map amendment](https://www.iso.org/standard/89044.html). The two Chinese HEIF attachments were unavailable during this review. The public English preview exposed definitions but not 6.6.2.4; this repair retains the existing HEIF graph/codec contract and does not claim a new full-text HEIF conformance review.
- [ICC.1:2022](https://www.color.org/specifications/ICC.1-2022-05.pdf), header/tag structure, 9.2.17 and 10.3; [H.273 (07/2024)](https://www.itu.int/rec/T-REC-H.273-202407-I) for CICP code points. RGB ICC matrix 0 and compressed gain nclx matrix 6 describe separate encodings.
